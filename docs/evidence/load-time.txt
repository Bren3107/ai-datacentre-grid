Load time of the deployed app (check 4.1: the deployed URL loads in under five seconds)

Measured 14 Nov 2026, 10:18 UTC (21:18 in Sydney), from a home connection in Sydney, with
scripts/measure_load.py. The run was after main f1178a9 merged, and before the v1.0-submission tag.
The tag goes on the commit that adds this file. That commit changes only docs/evidence, so the app
code is the same. To run it again:
    python scripts/measure_load.py

Method. Each cold run uses a new browser profile, so nothing is cached. This is the same as DevTools
with "Disable cache" ticked, which is how BUILD_PLAN section 6 step 4 and DEPLOY_CHECKLIST measure it.
DOMContentLoaded and Load are the page's own navigation timing. They are the two figures that
DevTools prints in the Network status bar. "question" and "4 charts" are the seconds until the
question heading, then all four charts, appear inside the app.

Reading. Load, the figure that DevTools reports and that our plan measures, was 3.4 to 3.7 s with
an empty cache. That is under 5 s. Content takes longer. With an empty cache the question appeared
after 6.6 to 7.6 s, and all four charts after 9.9 to 11.1 s. On a repeat visit these times were
3.0 to 3.1 s and 4.6 to 4.8 s. Most of the empty-cache time is the browser download of Streamlit's
and Plotly's own code. If a marker times visible content on a first visit, this check can fail.
